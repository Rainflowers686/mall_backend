# Security and data reports

This repository is a student project. Reports are handled on the current default branch; no response-time or security-support guarantee is made.

If you find an exposed credential, private data or an exploitable issue, avoid posting the value, personal records or a working exploit in a public issue. Use GitHub's private vulnerability-reporting option if it is available on the Security page. Otherwise open an issue that describes only the affected area and asks the maintainer for a private reporting channel.

Include the affected commit, file or endpoint, the impact and a minimal reproduction with synthetic data. A leaked credential must be revoked or rotated at its provider; removing it from the latest file does not remove earlier Git history.

## 中文说明

发现凭据、私人数据泄露或可利用的问题时，请勿把具体秘密、个人记录或完整利用方法写进公开 Issue。若 Security 页面提供私密漏洞报告入口，可使用该入口；否则只说明受影响范围，并向维护者请求私下沟通渠道。

报告应包含提交版本、文件或接口、影响和使用虚构数据的最小复现。有效凭据一旦泄露，需要在服务商处撤销或更换；只修改最新文件无法消除历史记录。
